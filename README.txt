Если переменная задана и экспортирована, launch-saved-retry.py использует
её автоматически: локальная форма не открывается, доступ проверяется API.
Если переменная отсутствует или пуста, остаётся прежняя локальная форма.
Некорректное значение отклоняется без вывода самого токена.

Выполняйте запуск из Терминала, в котором доступна переменная:

    cd /Users/safoncev/yandex-disk-backup
    python3 launch-saved-retry.py --client-id CLIENT_ID

CLIENT_ID — идентификатор приложения, а не токен. Токен не указывайте
аргументом команды. Запуск с уже действующим брокером по-прежнему
выполняется через start-retry-remaining.py; второй брокер не создавайте.

Если пользователь сохранил export YANDEX_DISK_TOKEN в ~/.zshrc, новый
интерактивный zsh прочитает его при открытии Терминала. Уже запущенные
приложения, включая Codex, автоматически новое окружение не получают.
~/.zshrc хранит значение открытым текстом; доступ к файлу ограничьте
правами 600. Скрипт сам этот файл не читает и не печатает токен.

Проверка только наличия переменной без вывода её значения:

    [ -n "${YANDEX_DISK_TOKEN:-}" ] && echo set || echo unset

Проверка доступности оставшейся очереди без скачивания содержимого:

    cd /Users/safoncev/yandex-disk-backup
    python3 authorize.py --availability-only --volume /Volumes/KINGSTON --workers 128 --client-id CLIENT_ID

Замените CLIENT_ID на идентификатор своего OAuth-приложения. Токен
вводится только в открывшуюся локальную форму. Проверка делает один
свежий запрос ссылки и проверяет ответ GET до заголовков для каждого
файла очереди. Тело ответа не читается, очередь миграции не меняется.

Отдельный прогресс и результаты проверки в папке со скриптами:
    availability-progress.json
    availability-results.jsonl
    availability-summary.json

available_headers_only_count: сервер ответил HTTP 200/206. Полный файл
этим ещё не проверен. unavailable_in_check_count: отказ в текущем
запросе. inconclusive_count: временная ошибка или неопределённый ответ.

Для запуска докачки с новой авторизацией после переноса или перезагрузки:

    python3 launch-saved-retry.py --volume /Volumes/KINGSTON --journal-path /Users/safoncev/yandex-disk-backup/journals/kingston-B3479192-F945-325C-9926-498190DFBD89/verified.sqlite3 --client-id CLIENT_ID

Для предварительной проверки добавьте --check. Саму докачку эта проверка
не запускает. CLIENT_ID является идентификатором приложения, не токеном.
Команда проверяет очередь и отсутствие другого загрузчика, затем печатает
LOCAL_AUTH_URL. Откройте этот адрес и введите токен только в форму.
Дождитесь downloading_saved_failures; после этого команда завершается,
а загрузка продолжается в фоне. Ввод токена ожидается до 20 минут.

Настройки диска и локального журнала сохраняются в target.json. После
первой подготовки --volume и --journal-path можно не указывать.
Работающий старый управляющий процесс сначала нужно завершить штатно;
второй одновременно не запускается. --availability-only выполняет
отдельную проверку доступности, а не докачку.

На exFAT готовый файл сохраняется через создание без перезаписи. После
копирования на место он повторно проверяется по размеру и MD5. Ошибка
локальной записи останавливает проход, исходный .partial сохраняется.
Если после сбоя остался несовпадающий целевой файл, мигратор остановится
для разбора, а не перезапишет его.

Старые 198,51 ГБ после переноса на другой диск повторно не хешируются
перед стартом этой очереди. Их прежний результат показывается отдельно
от подтверждения целостности перенесённой копии. Завершение очереди
само по себе не подтверждает целостность всей старой копии.

ОСНОВНЫЕ КОМАНДЫ

Сначала откройте Терминал и перейдите в папку со скриптами:

    cd /Users/safoncev/yandex-disk-backup

Все команды ниже выполняются из этой папки. Внешний диск должен быть
подключён как /Volumes/KINGSTON. Настройки берутся из target.json. В нашей конфигурации установлено 128
одновременных загрузок; команда докачки проверяет это значение.

На каждый файл предусмотрено до трёх попыток за один проход:
первая попытка и до двух повторов при неудаче. После успешной загрузки
и проверки повторы прекращаются. Каждая попытка получает свежую ссылку
на файл и заново проверяет размер и MD5. Между неудачными попытками
выдерживаются паузы 1 и 2 секунды.

Если все три попытки неудачны, файл остаётся в очереди недокачки.
Он учитывается как один недокачанный файл, а не как три файла.
Ошибки авторизации и записи на внешний диск останавливают проход;
команда паузы также прерывает ожидание повторов.

1. Продолжить докачку после паузы

    python3 start-retry-remaining.py --resume-paused

Команда использует сохранённый список и очередь недокачанных файлов,
а также авторизацию работающего управляющего процесса. Повторно
вводить токен в этом сеансе не нужно. Команда завершится после
подтверждения запуска; само скачивание останется работать в фоне.

Этот режим предназначен для остановленной очереди докачки. Новый общий
список файлов перед ним не собирается. В конце прохода выполняется
сверка папок через API. Уже проверенные неизменившиеся файлы сохраняются.

2. Проверить готовность к докачке, ничего не запуская

    python3 start-retry-remaining.py --resume-paused --check

При успехе в ответе будет status: paused_retry_ready и workers: 128.
Проверка не запускает загрузку и не меняет счётчики или очередь.
Её нужно выполнять, когда докачка стоит на паузе. Во время работающей
загрузки отказ этой проверки ожидаем: второй загрузчик не запускается.

3. Поставить скачивание на паузу

    python3 pause.py

Команда останавливает загрузчик и ждёт подтверждения остановки,
сохраняя готовые файлы, журнал проверки и очередь докачки.
Управляющий процесс с авторизацией остаётся работать.
Если команда запуска докачки ещё не завершилась, пауза может отказать
из-за занятой блокировки. Дождитесь завершения команды запуска,
затем повторите pause.py. Второй загрузчик при этом не создаётся.
Дождитесь подтверждения paused. После этого можно отключить внешний
диск. Если команда сообщает, что остановка ещё не завершена,
проверьте статус и дождитесь остановки перед отключением диска.

По умолчанию ожидание длится до 90 секунд. Увеличить его до трёх минут:

    python3 pause.py --timeout 180

Если после timeout процесс уже завершился, повторный запуск pause.py
подтвердит паузу и сохранит итоговый статус без нового сигнала.

Незавершённые файлы в .partial ещё не прошли проверку. При следующем
запуске такой файл может скачиваться с начала: возобновление по байтам
в этой версии не реализовано. Уже проверенные готовые файлы не теряются.

4. Проверить, что командой паузы выбран правильный процесс

    python3 pause.py --check

Это проверка без остановки: сигнал загрузчику не отправляется,
файлы состояния не изменяются. Для самой паузы выполните команду
из пункта 3 без --check.

5. Показать статус один раз

    python3 watch.py --once --summary-only

Выводит этап, число потоков, общий сохранённый объём и очередь недокачки.

6. Показывать текущие действия и статус постоянно

    python3 watch.py

Обновление каждые пять секунд. Показываются скачиваемые файлы,
полученные байты, стадии проверки и сводные счётчики.
Для активного файла показывается номер попытки, например 2/3.

Только сводка, без отдельных файлов:

    python3 watch.py --summary-only

Другой интервал обновления, например десять секунд:

    python3 watch.py --interval 10

Ctrl+C в окне watch.py закрывает только монитор. Скачивание продолжится.
Чтобы остановить именно скачивание, используйте python3 pause.py
в другом окне Терминала или после закрытия монитора.

7. Повторно попробовать недоступные файлы после законченного прохода

    python3 start-retry-remaining.py

Используйте эту команду, если проход уже закончился с этапом
complete_with_errors, а управляющий процесс ожидает повторного запуска
с return_code: 2. Она запускает один новый проход сохранённой очереди.
Для обычной паузы используйте --resume-paused из пункта 1.

Не ставьте эту команду в бесконечный цикл. Недоступные файлы остаются
в очереди, и их можно повторно попробовать позже.

8. Справка по параметрам

    python3 start-retry-remaining.py --help
    python3 pause.py --help
    python3 watch.py --help


КАК ЧИТАТЬ СТАТУС

«Сохранено и проверено всего» — результат предыдущих проходов и текущей
докачки. После переноса прежние файлы ещё не прошли повторную проверку
целостности на Kingston; prior_copy_integrity_confirmed=false отражает это.

«В этой очереди проверено» — результат только текущего прохода очереди.
При новом запуске этот счётчик может начинаться с нуля. Общий сохранённый
результат при этом не теряется.

«В очереди недокачки» — файлы, которые пока не удалось полностью
сохранить. Сюда входят ещё не обработанные файлы и текущие загрузки.
Это не число новых HTTP-ошибок за текущий запуск.

«Завершено обработок» и «неудачных» — законченные попытки текущего
прохода. Текущая очередь уменьшится после успешной загрузки и проверки.

«Непроверенных данных в активных загрузках» — байты незавершённых файлов.
Они не включаются в полностью сохранённый объём.

complete_with_errors означает частичную копию с очередью для докачки.
failed_waiting_retry при return_code: 130 означает остановку после паузы;
при return_code: 2 — завершение прохода с недоступными файлами.
Полная копия подтверждается итоговой сверкой, а не только окончанием
передачи файлов.

ЕСЛИ УПРАВЛЯЮЩИЙ ПРОЦЕСС ЗАВЕРШИЛСЯ ИЛИ MAC ПЕРЕЗАГРУЖЕН

Токен хранится только в памяти процесса. После его завершения команда
--resume-paused не может восстановить авторизацию автоматически.
Сохранённые данные остаются на внешнем диске, новый журнал проверки
на внутреннем диске Mac. Сохраните оба, а также папку мигратора.

Справка по служебным скриптам авторизации и первого полного прохода:

    python3 authorize.py --help
    python3 download.py --help

Эти команды показывают справку служебных скриптов и ничего не запускают.
Для восстановления очереди с новым токеном выполните:

    python3 launch-saved-retry.py --client-id CLIENT_ID --check
    python3 launch-saved-retry.py --client-id CLIENT_ID

Эти сокращённые команды используют уже сохранённый target.json.
При первой подготовке явно укажите --volume и --journal-path, как в начале
инструкции. Команда допускает только 128 потоков; загрузчик делает до
трёх попыток на файл. Новый список всего облака перед стартом не нужен.
Прямой authorize.py без подготовленного режима очереди использовать
не следует. Токен вводите только в локальную форму, не в команду и не в чат.
Не создавайте второй управляющий процесс, пока старый жив. Обычная
пауза оставляет его работающим и сохраняет авторизацию этого сеанса.

В этой рабочей версии команда --resume-paused рассчитана именно на
паузу докачки, а не на паузу первоначального полного прохода.
